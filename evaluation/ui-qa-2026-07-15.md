## 이번 QA에서 수정한 문제

1. `config.limits.promptChars`가 실제 호출 경로에 연결되지 않았던 문제를 수정했다. 문자 수와 UTF-8 byte 수 중 하나라도 한도를 넘으면 Claude/Codex brain caller를 시작하지 않는다.
2. Harness를 편집하는 동안 서버의 새 Harness 이벤트가 도착하면 로컬 기준 version까지 바뀌어 충돌 검사가 약해질 수 있던 문제를 수정했다. 편집 시작 시점의 version을 유지해 저장 시 서버가 충돌을 검출한다.
3. Harness 원문으로 되돌려도 dirty 상태가 남던 문제를 수정했다.
4. 새 세션 생성 성공 뒤 이전 Harness dirty 상태가 남을 수 있던 문제를 수정했다.
5. 1280px 화면에서 펼친 rail 때문에 대화:ledger가 약 2.9:1까지 축소되던 문제를 `3.67:1`로 보정했다. rail을 접으면 정확히 `4:1`이다.
6. 200px ledger에서 header와 Harness 저장 행이 가로로 밀리던 문제를 줄바꿈 가능한 레이아웃으로 보완했다.
7. canonical 평가 Harness에 `HARNESSING → harness_set → dispatch`, 3역할 스키마, pinned revision, 사용자 override 주입, injection canary 비노출 게이트를 추가했다.

## 남은 권고 사항

### 우선순위 높음

- 신뢰하지 못하는 외부 문서를 입력받기 전에는 AI Council을 전용 저권한 Windows 계정, Windows Sandbox 또는 VM에서 실행한다. Codex `read-only`는 파일 쓰기를 제한하지만 현재 사용자에게 읽기 권한이 있는 파일을 숨기는 OS 보안 경계는 아니다.
- Playwright 기반 DOM 회귀 스위트를 프로젝트 테스트에 추가한다. 최소 viewport는 `375`, `768`, `1440px`이며, rail drawer, inspector, composer 겹침과 keyboard focus를 자동 검증한다.
- dirty Harness 중 SSE 갱신, stale-session `409`, 페이지 이탈 취소, Markdown/XSS payload를 자동 브라우저 테스트로 고정한다.

### 후속 안정화

- `sessions-index.json` 손상 시 `sessions/*.json` 재스캔 복구 테스트를 추가한다.
- snapshot 교체 단계별 강제 종료, 100개 session registry 정리, orphan snapshot 정책을 검증한다.
- SSE 연결 수 제한, slow-client backpressure, 비정상 `Last-Event-ID`, transcript retention gap의 full-state reset을 구현·검증한다.
- 다음 버전에서 결과물 export와 4~7단계 제작·상호 검수 workflow를 연결한다.
